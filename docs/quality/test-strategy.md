# 测试与验收策略

## 1. 质量门槛

每次合并至少通过 lint、格式、typecheck、单元测试、受影响集成测试、构建和文档链接/表格结构检查。数据库迁移需在空库和上一版本快照上验证。P0 发布前通过端到端主路径、安全隔离、队列恢复和基础负载测试。

## 2. 测试层级

| 层级     | 重点                      | 示例                                          |
| -------- | ------------------------- | --------------------------------------------- |
| 单元     | 纯领域规则和映射          | 状态机、评分、费用、权限、错误分类            |
| 模块集成 | 数据库/Redis/私有文件适配 | 幂等创建、Outbox、账本、租户过滤、文件越权    |
| 契约     | OpenAPI、Provider、Skill  | DTO 兼容、供应商错误映射、Skill schema        |
| E2E      | 用户可见主路径            | 建项目→确认→Prompt→分析→报告                  |
| 安全     | 越权与不可信输入          | 跨租户、SSRF、注入、密钥回显、验证码滥用      |
| 恢复     | 重复、超时和组件故障      | Redis 重启、重复消息、模型超时、Telegram 失败 |
| 性能     | PRD 指标与长任务吞吐      | 列表 P95、详情 P95、队列并发                  |

第三方 API 默认使用契约模拟器；少量 staging smoke test 调真实 sandbox/provider，禁止 CI 无上限消费真实模型。

## 4. 关键属性测试

- 总分始终在 0–100；权重和为 1（或经明确归一化）；空样本不产生伪 0 分。
- Job 计数满足 `completed + failed + cancelled + pending/running = totalRuns`；取消时已有成功结果进入 `partially_completed`。
- UsageLedger 同一幂等键最多一个业务效果；冲正后净额正确。
- 状态机只允许文档声明的转换，终态不能被普通更新恢复。
- 时间跨 DST/项目时区时，定时窗口仍恰好执行一次。
- 相同告警 fingerprint 在抑制窗口内不重复轰炸，恢复只关闭对应事件。
- 认证 Challenge 在并发验证时最多创建一个 Session；错误尝试达到 5 次后立即失效。工作区跨租户读取统一为 404，最后 owner 在并发角色变更/移除下仍至少保留一人。

## 5. 性能验收

- 普通列表 API P95 < 800ms；关键详情 P95 < 1.5s，在预先约定的数据量与并发下测量。
- HTTP 请求不等待模型、抓取、解析和评分长任务完成。
- 单个火山 Model ID 故障不会阻塞其他模型配置；火山方舟整体故障时不自动调用其他原厂，Job 按部分成功/失败规则收敛并可恢复。
- 报告和管理首页使用可解释缓存，缓存失效不返回跨租户数据。

具体压测数据规模和并发在 Epic 0 确认，避免只写无条件的毫秒目标。

## 6. 测试数据

建立最小固定 fixture：无门店品牌、单店、本地连锁、多城市大型连锁、同名品牌、无官网品牌；模拟模型回答包含不提及、多个竞品、别名、拒答、空响应、非结构化响应和事实错误。测试数据不得复制真实用户隐私或生产密钥。

## 7. 发布检查

- 迁移备份和回滚/前向修复方案已演练；
- Provider/Telegram 外部依赖有降级；
- 关键 dashboard、日志、trace 和告警可用；
- staging 完成主路径与权限 smoke test；
- staging 通过 Vite SPA 构建、Cloudflare Pages 深层链接刷新、`chatway.chat` 自定义域名会话、OpenClaw 固定版本、火山方舟适配器和四类 ModelConfig 契约 smoke test；
- 已知限制写入发布说明并关联开放问题；
- 发布后检查错误率、延迟、队列、成本和报告成功率。

## 8. E2 应用壳回归

- API 客户端单测覆盖 credentialed Cookie、CSRF、设备/请求 ID、工作区缓存清理和在途响应隔离。
- 项目二级导航使用 capability 纯函数测试，隐藏模块不改变服务端授权要求。
- 浏览器专项检查用户登录页、用户端抽屉和管理审计入口；390、768、1024、1440px 均不得出现页面级横向溢出，320px 额外检查最小边界。
- 邮件/API 失败时登录页必须停留在邮箱步骤并显示可恢复错误，不能错误进入验证码步骤。

## 9. E3 项目与认知源回归

- API 集成测试覆盖缺少 CSRF、项目幂等创建/参数冲突、跨工作区 404、识别事件重复消费和人工确认。
- 认知源回归覆盖归一化去重、抓取任务幂等、快照正文和重复事件；安全单测覆盖 IPv4/IPv6 私网、DNS 重绑防护、重定向到私网和解压后大小上限。
- 浏览器冒烟验证项目创建表单的必填状态、移动抽屉和 320/390px 单列表单；页面无 console error。

## 10. E4 Prompt 回归

- 纯规则单测覆盖 Unicode/标点归一化、诱导用语拒绝、地域 Scope 必填和双字符相似度。
- API 集成测试覆盖生成建议、缺少地域时阻断、诱导 Prompt 拒绝、人工新增、乐观锁编辑、不可变版本序列、变体和软删除。
- 前端回归检查分类/Scope/地域动态字段、启停、批量导入、变体和版本历史；窄屏下表格转卡片且操作不溢出。

## 11. E5 Model Gateway 回归

- 单元测试覆盖 AES-256-GCM 凭证往返、方舟 Chat Completions 响应映射、显式原生联网参数，以及 401/403、429、5xx、超时和策略拒绝分类。
- API 集成测试覆盖管理登录/二次验证、凭证不回显、Provider 前置条件、四模型族独立启停、需联网组合跳过、估算和额度幂等。
- 调用隔离测试使一个 Model ID 失败、另一个成功，断言批次返回部分成功；调用日志必须包含 Token/成本/耗时/错误/重试，且不包含 API Key 或完整 Prompt/响应。
- 真实方舟账户的 Model ID、价格和原生联网能力只在 staging 使用受限额度做 smoke test；CI 始终使用虚构 ID 和契约模拟。

## 12. E6 分析任务回归

- API 集成测试覆盖同幂等键只产生一个 Job/一笔预留，PromptVersion × ModelConfigVersion 精确拆分，且跳过组合不进入 `totalRuns`。
- 契约模拟同时返回一个成功和一个可重试失败，Job 必须收敛为 `partially_completed`；全失败收敛为 `failed`，重试不新建逻辑 Run。
- 取消测试验证未运行组合全部转为 `cancelled`；已有成功结果时为 `partially_completed`。重复事件由 Run 原子认领和 InboxReceipt 防重。
- 额度回归断言 reservation/release/actual-cost 均为只追加幂等记录；Redis 丢失时 Outbox reconciliation 可重投，超时 `running` 记录转 `outcome_unknown` 而不自动再扣费。

## 13. E7–E8 解析、评分与报告回归

- golden dataset 覆盖提及/未提及、推荐、顺位、别名、多竞品、情感和事实标签；`score-v1` 对相同输入保持确定性，空样本不伪造 0 分。
- API 集成覆盖低置信实体审核、竞品确认/排除、分数版本与证据；报告生成必须冻结 Job/Score/内容/限制说明，发布与归档不能原地覆盖历史。
- 部分成功报告明确缺失模型和样本限制；查看事件、优化建议和站内通知不改变报告快照。

## 14. E9 管理后台回归

- 管理首页、用户、项目、任务、模型调用和审计筛选均读取真实数据库投影；非白名单管理登录、普通用户和缺少二次验证的敏感写操作必须拒绝。
- 用户状态与额度调整做参数、权限、审计和失败路径测试；管理 UI 不显示密钥、完整 Prompt 或模型原文。

## 15. E10 OpenClaw 与 Agent 回归

- 契约测试固定官方 `/v1/chat/completions`、`openclaw/default`、bearer auth、超时和 Token 上限；OpenClaw 自定义 Provider 只能回调内网 Model Gateway，生产镜像必须固定官方 digest。
- Skill Registry 启动校验只允许已声明的只读/低风险 Skill；注入文本不能新增 Skill，高风险工具不存在，写 Skill 缺少幂等键必须失败。
- AgentRun/AgentAction 保存状态、引用、Token 和审计；模型只接收应用服务已验证的证据，跨租户 ID、证据内指令或 OpenClaw 输出都不能扩大权限。

## 16. E11 通知与 Telegram 回归

- `report.ready` 重复消费只为每个成员创建一条站内通知；列表只返回当前用户，已读操作需要 CSRF 且不能跨用户修改。
- Telegram Token/Chat ID 加密保存并只返回掩码；配置和测试均要求白名单管理员及二次验证，响应、日志、审计和数据库非密文字段不得出现 Token。
- 测试消息覆盖幂等、每分钟 3 次限流、401/403、429、5xx、超时、响应异常与投递日志；渠道失败不回滚主业务。

## 17. E0-S9 数据生命周期回归

- 集成测试创建超过 180 天的网页正文快照，验证 project 法律保留生效时正文不变，释放后下一幂等窗口清空正文并保留哈希/元数据；创建、释放、跳过和清理均有审计。
- 路径安全测试拒绝私有文件根目录本身、绝对越界和 `..` 越界；文件不存在视为可重入成功，其他文件错误保留数据库路径并使任务重试，3 次后进入死信。
- 管理 API 测试覆盖管理员身份、CSRF、10 分钟二次验证、Scope 存在性和 Token/正文不回显。模型响应、网页快照和 Agent 对话分别验证 180 天边界；审计日志不得被该任务删除。
