# 用户流程与页面清单

## 1. 核心流程

### 1.0 邮箱验证码登录

1. 用户输入邮箱，系统统一提示“如果地址可用，将发送验证码”。
2. Auth 服务创建短期验证码挑战并通过 Resend 发信。
3. 用户输入验证码；验证成功后自动创建账号（首次）或登录，并建立安全 Session。
4. 失败、过期、频率限制和次数耗尽均提供可恢复提示，但不暴露邮箱是否已注册。

管理端使用同一验证码机制，但请求携带 `audience=admin`。P0 只对 `geyaovip@163.com` 发送管理验证码并建立 `super_admin` 会话；其他邮箱统一提示无法完成管理登录，不泄露白名单内容。这不影响 `app.chatway.chat` 的普通用户登录。

### 1.1 创建项目与首次分析

1. 用户填写品牌/商家名称、主要市场、默认语言，可选官网和行业。
2. 系统创建草稿，优先使用用户输入和官网。需要联网发现时，只调用已接入模型本身的官方联网能力生成品牌/官网/来源候选；无原生联网能力时不调用外部搜索。
3. 用户确认、修正、删除或新增候选；模型候选引用在用户确认前不自动深度抓取。识别失败时至少确认一个认知源，或保留草稿。
4. 系统保存实体与来源，生成适用模块、Prompt 建议和模型建议。
5. 用户确认 Prompt、模型、地域、门店范围、语言及报告/通知选项。如果 Prompt 需要联网，界面显示哪些模型无原生联网能力并自动跳过该组合。
   如果 Prompt/Scope 需要国家、城市、区县或地标但项目没有相应内容，必须暂停并让用户填写，不能由模型猜测。
6. 系统展示运行次数、预计耗时、预计额度/成本；用户确认后入队。
7. 前端显示任务进度、部分失败和可取消状态。
8. 任务完成后展示分数、置信度、证据、竞品和优化建议。

### 1.2 优化与复测（P2）

```text
报告问题 → 创建优化项 → 执行 → 审核 → 选择相关 Prompt
→ 推荐模型 → 复测 → 对比基线 → 改善/无变化/下降 → verified
```

### 1.3 管理端告警（P1）

```text
指标采集 → 规则命中 → AlertEvent(open) → 去重/合并
→ 可选 Agent 分析 → 管理站内/管理员 Telegram → acknowledge → resolved → 恢复通知
```

告警判断不得依赖 Agent 自由推理；P0/P1 事件需具备确定性规则和阈值。

### 1.4 Agent 中风险动作（P2）

```text
提出动作 → 校验 Skill 与触发者权限 → 创建 waiting_confirmation 的 Action
→ 展示影响范围与参数 → 有权人员批准/拒绝 → 幂等执行 → 审计结果
```

### 2.1 项目动态二级导航

- 始终显示：概览、品牌信息、AI 可见度/报告、Prompt、竞品、认知源、优化建议、历史报告、项目设置。
- 识别到官网后显示“官网”专项模块。
- 存在有效门店后显示“门店”和“城市与区域”。
- P1 上线品牌管家后显示“品牌管家”。
- 隐藏模块仅影响展示，不能替代权限和数据存在性检查。

## 4. 全局 UX 状态

每个数据页必须设计：加载、空数据、无权限、部分数据、失败、过期数据和重试状态。长任务使用轮询或 SSE；断线重连后以服务端状态为准。所有危险操作展示对象、影响范围和不可逆后果。

用户端必须按 `ui-design-system.md` 实现自适应布局。管理端以桌面为主要使用环境，但基础查看、告警确认和测试消息仍不得在移动端不可用。

## 5. 验收用页面规则

- 页面展示的状态、分数、成本和进度来自真实 API，不从客户端推断业务终态。
- 所有错误显示稳定错误码与用户可理解信息，并带可关联的请求 ID。
- 多租户页面切换工作区后清除旧缓存；URL 中项目必须属于当前工作区。
- 日期显示项目或用户时区，并明确标注；导出数据默认带时区。
- 分数页同时展示样本量、成功率、置信度与 `scoreVersion`。
