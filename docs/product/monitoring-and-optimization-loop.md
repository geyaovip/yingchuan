# 数据洞察、监测计划与优化复测

## 范围与依据

2026-10-13 用户确认在公开 AnswerBit 资料对标的基础上统一优化。首批增加数据洞察、问题与竞品表现、引用排行、自动监测、优化任务和同条件复测。所有指标来自已落库的模型回答，不引入消费端模型抓取、外部搜索或自动发布。

## E12-S1 数据洞察

- 近 7/30/90 天，按模型、问题和问题分组筛选；仅统计成功且解析有效、未截断的回答。
- 提及率为提及品牌的有效回答数 / 有效回答数；推荐率同理。平均排名仅使用明确编号，附排名样本数。无样本显示空值。
- 竞品仅使用已确认竞品，同分母计算。问题与模型表现可追溯到回答。
- 趋势按模型版本、问题版本、地域 Scope、联网策略、解析版本、评分版本划分独立比较组；数据不足的点保留诊断标识。不同组不连线。
- 引用按回答去重，分别聚合域名和文章；仅接受 HTTP(S)，去除片段和常见追踪参数。提供各模型引用次数和回答入口。
- 超过 500 次任务或 20,000 条回答时要求缩小范围，不能静默截断。

## E12-S2 监测计划

- 项目时区，每日或每周指定时间；明确选择启用问题与模型、单次费用上限。执行时使用所选配置最新版本。
- 创建/编辑/暂停/恢复均要求 analysis.run；执行前再次验证创建者账号、工作区权限、项目状态和所选配置。
- 模型价格未配置时阻止监测与复测，不能按免费调用估算。单次上限是模型输出预算估算的准入限额，实际费用按现有模型网关记录和额度账本结算；并非外部供应商的硬计费承诺。
- 创建计划要求 Idempotency-Key，同请求重放返回同计划，键被用于不同内容时拒绝。
- 失败站内通知通过通知应用服务写入，与执行结果共用事务；监测模块不直接修改通知表。
- 唯一执行键 scheduleId + dueAt；记录配置快照、尝试次数、租约、错误、分析任务与审计关联。租约两分钟，最多三次重试，重试间隔一分钟。崩溃后使用相同分析幂等键恢复；多 Worker 不重复提交。
- 修改计划仅影响后续执行，已到期任务保留原配置；每个项目最多 20 个计划。
- 长时间停机只补一个到期任务，下一次排到未来；暂停后不新增任务，已提交分析继续执行。预算不足、权限撤销、配置失效记跳过并站内通知；重试耗尽进死信。已有 report.ready 通知负责报告到达。

## E12-S3 优化任务与复测

- 创建任务时选择真实历史分析作为基线；支持负责人、截止时间、措施与证据链接，状态待处理/进行中/已完成。
- optimization.manage 管理任务；负责人必须是本工作区活跃成员。版本号防止覆盖并发修改。所有写操作审计。
- 复测需 analysis.run，并确认费用。复制基线任务原始问题版本、模型版本、Scope 与联网策略，禁止把当前版本冒充同条件。供应商/模型停用或权限变化时阻止提交。
- 每次复测用独立幂等键，复测记录与分析任务关联；重试同请求返回同一次分析。已有异步分析机制负责超时、重试和死信。
- 对比仅在评分和解析版本一致、相同配置与完整有效样本条件下展示评分变化；样本不足或失败时展示限制，不能宣称提升。任务完成不自动代表效果验证。

## 接口与状态

均沿用登录会话、Origin 校验；写接口额外要求 CSRF。资源权限在服务端校验。

| 方法  | 路径（前缀 /api/v1）                             | 用途                                          |
| ----- | ------------------------------------------------ | --------------------------------------------- |
| GET   | /projects/:id/insights                           | 统计与引用，days/modelId/promptId/group 筛选  |
| GET   | /projects/:id/monitoring                         | 计划、最近执行、可选问题/模型/负责人/历史基线 |
| POST  | /projects/:id/monitoring/estimate                | 所选组合或基线复测费用                        |
| POST  | /projects/:id/monitoring/schedules               | 新建计划                                      |
| PATCH | /projects/:id/monitoring/schedules/:scheduleId   | 乐观锁编辑/暂停/恢复                          |
| GET   | /projects/:id/optimization-tasks                 | 任务及复测                                    |
| POST  | /projects/:id/optimization-tasks                 | 新建优化任务                                  |
| PATCH | /projects/:id/optimization-tasks/:taskId         | 更新任务                                      |
| POST  | /projects/:id/optimization-tasks/:taskId/retests | 同条件复测                                    |

监测执行状态：pending → running → submitted；可重试错误回到 pending；准入失败 → skipped；第三次失败 → dead_letter。分析状态继续沿用 E6，不新增模型直连。

## 验收

单元测试覆盖分母、显式排名、引用去重、配置分组与时区。数据库集成测试覆盖权限/工作区隔离、限额、计划执行幂等、租约恢复、乐观锁、相同版本复测及通知。真实浏览器检查空/错误/有数据、创建/暂停/任务更新与复测确认、桌面及窄屏；通过仓库完整检查后发布。
