# 用户端 UI 与自适应基线

## 1. 设计方向

视觉参考 2026-07-22 的 Perplexity Web：首页采用克制的暖白画布、低对比侧栏、近黑正文、细边框、少阴影、胶囊控制和大留白；桌面端把主任务集中在内容区，移动端收起侧栏并把主要输入放在底部易触达位置。

映川只借鉴信息层级、留白和自适应思路，使用自己的品牌色、图标、文案、数据组件和交互，不复制 Perplexity 的商标或独特界面资产。

## 3. 布局

### 桌面端（≥ 1200px）

- 固定 224px 左侧导航；内容区独立滚动。
- 页面内容最大宽度 1280px，左右留白至少 24px。
- 概览页使用 12 列网格；核心总分和异常优先于辅助统计。
- 过滤器、时间范围和主要操作保持在页面标题区，不堆积多层工具栏。

### 平板（768–1199px）

- 侧栏折叠为图标栏或抽屉；内容区使用 8 列网格。
- 四列指标卡降为两列；右侧详情面板可转抽屉。
- 表格保留关键列，次要字段进入行详情。

### 移动端（< 768px）

- 不保留固定侧栏，使用顶部栏 + 抽屉导航。
- 内容单列，左右间距 16px，主要按钮最小高度 44px。
- 指标卡单列或两列；宽表优先转换为卡片/分组列表，确需横向滚动时固定首列并明确提示。
- 底部操作区避开安全区域；长表单分段，固定操作不得遮挡内容。
- 图表提供文字摘要和可访问的数据表入口。

## 4. 核心组件

- `AppShell`：工作区、主导航、项目二级导航、移动抽屉和统一账号菜单；退出登录不直接挤占侧栏空间。
- `PageHeader`：标题、范围、更新时间、主要操作。
- `MetricCard`：值、变化、样本量、置信度和状态，不只显示孤立数字。
- `ScoreCard`：总分、scoreVersion、置信度和限制说明。
- `EvidencePanel`：模型回答片段、来源、时间和解析置信度。
- `DataTable/ResponsiveList`：桌面表格与移动卡片共享字段配置。
- `StatusBadge`：文本 + 图标 + 颜色三重表达。
- `TaskProgress`：总数、完成、失败、取消、预计剩余时间。
- `Empty/Error/StaleState`：给出原因和下一步操作。
- `ConfirmDialog`：展示目标、影响范围、风险和幂等执行结果。

## 5. 页面密度

- 项目概览保持“结论优先”：总分、变化、最重要问题、下一步任务位于首屏。
- 报告和 Agent 页面保持阅读宽度，正文建议不超过 760px；证据和元数据可使用侧栏/抽屉。
- Prompt、任务、门店和管理列表属于高密度页面，可使用紧凑表格，但行高不低于 40px。
- 页面标题只保留当前任务、必要说明和主要操作；不使用重复的英文眉题或装饰性编号。
- 应用导航和状态反馈使用统一图标组件，不使用文字符号模拟图标。
- 不为装饰增加大面积渐变、玻璃效果或无业务意义的动画。

## 6. 交互与响应式验收

- 在 390、768、1024、1440px 宽度完成关键页面截图或浏览器测试。
- 320px 宽度不得出现页面级非预期横向滚动。
- 键盘可完成导航、表单、对话框和主要表格操作；焦点清晰可见。
- 支持 `prefers-reduced-motion`；动画只用于状态和空间关系。
- 加载时使用保持布局的 skeleton；长任务状态以服务端为准。
- 桌面和移动端展示相同业务事实，不以隐藏关键数据实现适配。
