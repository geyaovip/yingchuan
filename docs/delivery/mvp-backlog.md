# MVP 开发 Backlog

> 上下文提示：开发代理应先用 Story ID 搜索，只读取当前 Story 所在 Epic；不要默认加载本文全部 Story。

## 1. 计划原则

- P0 先完成单个品牌端到端闭环，再扩展门店、告警和复测。
- 每个 Story 必须有可演示的业务结果，不以只有表结构或静态页面作为完成。
- 依赖的开放问题未解决时可做 spike/接口抽象，不能合并不可逆供应商逻辑。
- Story 完成定义遵循仓库根目录 `AGENTS.md`。

## 3. Epic 与 Story

### E0 工程与平台基线

- **E0-S1 Monorepo 初始化**：建立 apps/packages/modules、包管理、lint、format、typecheck、test、build。
- **E0-S2 本地依赖**：PostgreSQL、Redis、本地私有文件目录与 `.env.example`，使用 `COMPOSE_PROJECT_NAME=yingchuan` 一条命令启动隔离的开发环境。
- **E0-S3 数据迁移与种子**：Prisma Migration、测试数据库、权限/行业/模型测试 fixture；生产不使用测试数据。
- **E0-S4 CI**：变更检查、迁移验证、测试、构建、文档链接与密钥扫描。
- **E0-S5 可观测基础**：结构化日志、request/trace ID、health/readiness、基础指标。
- **E0-S6 Outbox spike**：验证事务写入、消息派发、重复消费和 reconciliation，确认 D-013。
- **E0-S7 部署基线**：Web/Admin Vite SPA 构建到 Cloudflare Pages，配置 `app.chatway.chat`/`admin.chatway.chat` 和深层路由；`api.chatway.chat` 用 DNS-only 记录指向共享云服务器 Caddy/Let's Encrypt，部署独立 `yingchuan` Compose project、持久卷、备份目录和 GitHub Actions 环境。
- **E0-S8 生产加固**：盘点共享宿主端口/资源，配置 TLS、防火墙、非 root 容器、独立 Docker network/DB 账户/Redis 隔离、resource limits、Secret 注入、备份恢复演练和最小运维账户。
- **E0-S9 数据生命周期**：按 D-023 实现到期删除、应用与私有文件一致性、审计和法律保留跳过。
- **E0-S10 产品官网**：在 `chatway.chat` 发布独立 Vite 静态官网，介绍产品能力和分析流程，提供前往 `app.chatway.chat` 的用户入口，并在 320/390/768/1024/1440px 保持可用。

验收：全新机器按 README 可启动；CI 可阻止类型、迁移和测试错误；前端产物不包含服务端代码/密钥；staging 可分别部署 Pages 与云服务器后端。

### E5 Model Gateway、火山方舟模型配置与用量

- **E5-S1 Provider contract**：请求/响应、能力、错误类别、request ID，并分离 `providerCode` 与 `modelFamily`。
- **E5-S2 火山方舟适配器**：使用一个方舟账户/API Key，从账户当前可用列表选择豆包、Kimi、GLM、DeepSeek 四类 Model ID，实测能力矩阵、超时、429/5xx 和策略拒绝映射。
- **E5-S3 原生联网与地域**：每次运行冻结模型原生联网开关/工具版本/引用；需联网但模型不支持时在估算中跳过该组合，不接外部检索；地域 Scope 缺失时要求用户填写。
- **E5-S4 模型管理**：价格版本、并发、状态、备用标记、密钥覆盖更新和审计。
- **E5-S5 估算与额度**：运行次数、价格快照、额度预留和追加式账本；不接真实支付。
- **E5-S6 调用观测**：Token、成本、联网费用、耗时、错误、重试且无密钥泄漏。

验收：火山方舟 Provider 和四类 ModelConfig 可分别启停；估算可解释；同幂等键不重复扣费；单 Model ID 失败不阻塞其他模型，火山整体故障能部分失败并清晰报错；联网与非联网可区分比较。

## 4. P0 后 Backlog

- **P1-A（已实现）告警调度**：Worker 每分钟按 UTC 窗口幂等评估模型失败率、队列等待、小时模型成本和报告耗时；相同 fingerprint 合并，30 分钟最多更新一次，恢复后关闭。管理端 `/admin/alerts` 展示真实事件；Telegram 配置启用后按立即发送及 1/5/15 分钟退避重试，最终失败不影响站内事件和主任务。
- **P1-B（已实现）运营日报**：每天 09:00（Asia/Shanghai）生成前一自然日不可变数据快照；相同日期幂等，失败最多重试 3 次后转死信，管理端 `/admin/daily-reports` 可查看。Telegram 已启用时按立即发送及 1/5/15 分钟退避推送；P0 无账务数据，付费用户和收入明确显示“暂无数据”。
- **P1-C（已实现）品牌管家**：只读问答，只调用已注册查询 Skill，并返回数据引用、时间范围和不确定性。
- P1 暂不承诺门店 CSV 和“高价值用户”告警。
- **P2**：数据质量审核；优化任务/复测；客服草稿；漏斗/产品分析；中风险审批；自定义模板和多渠道。
- **P3**：自动模型切换、高级多 Agent、封闭来源合规采样、企业 API、门店同步、全球多语言。
